# Instantáneas y commits

Git guarda tu proyecto como una serie de instantáneas. Cada instantánea se llama **commit**, y cada commit captura el estado exacto de todos los archivos bajo seguimiento en ese momento.

Tú decides cuándo tomar una instantánea. Un flujo de trabajo típico es así:

1. Edita algunos archivos.
2. Dile a Git qué cambios quieres incluir en la próxima instantánea.
3. Crea un commit con un mensaje breve que describa el cambio.

Cada confirmación recibe un ID único (una cadena larga de letras y números) y un mensaje que escribes tú, como `"Add login form"` o `"Fix typo in README"`.

Una vez creado un commit, siempre puedes volver a él. Aunque elimines archivos más adelante, la instantánea recuerda cómo eran antes.

## Cuestionario

1. ¿Qué ocurre con una confirmación después de eliminar los archivos que registraba?

- Respuesta: El commit sigue recordando como eran los archivos.

Una vez creado un commit, siempre puedes volver a él. La instantánea conserva el estado de los archivos aunque se eliminen más tarde.

2. Git crea commits automáticamente cada vez que guardas un archivo.

- Respuesta: `False`

Tú decides cuándo crear una confirmación. Git no toma instantáneas automáticamente cuando guardas archivos. Debes indicarle explícitamente a Git que cree una confirmación.

3. ¿Cuál es el orden correcto de los pasos en un flujo de trabajo típico de Git?

- Respuesta:  
  a. Editar archivos  
  b. Decirle a git que cambios incluir  
  c. Crear un commit con un mensaje

El flujo de trabajo típico es: hacer cambios, preparar los cambios que quieras y después crear un commit con un mensaje que describa el cambio.

4. ¿Qué es una confirmación en Git?

- Respuesta: Una instantánea de tu proyecto en un momento específico.

Un commit captura el estado exacto de cada archivo rastreado en el momento en que lo creas y funciona como una instantánea de tu proyecto.

5. Cada commit en Git tiene un ID único.

- Respuesta: `True`

Cada commit recibe un identificador único, una cadena larga de letras y números que lo distingue de todos los demás commits. (checksum - suma comprobatoria).
